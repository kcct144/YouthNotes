# 参与共建

## 学生：写一条，拍张照片就行

不需要电脑，不需要账号，也不用学 Markdown 或 Git。**自己做纸质笔记，拍张照片交给老师，剩下的整理由老师负责。**

不必写完整的一章，**只写一个知识点、一个考点、一个坑点，或者一张清单就可以**；一次交几条也行。

| 类型 | 写什么 |
| --- | --- |
| 知识点 | 这个概念是什么、为什么成立、什么时候不成立 |
| 考点 | 这类题怎么认出来、先做什么、完整走一遍 |
| 坑点 | 自己错在哪、错的原因、下次怎么检查 |
| 清单 | 需要记住、能快速查的事实：焰色反应、离子颜色、常见沉淀、常数，写清来源和适用条件 |

写的时候：

- 用**自己的话**说，不要整段抄教材；
- 有教材或题目来源就写上，写不清也可以先不写；
- 拿不准的地方标个问号，不必勉强写完整；
- 有图就画个图，比一大段文字更清楚。

拍照的时候：

- 整页拍全，不要裁掉边缘的公式或批注；
- 字迹和符号清楚，光线足够，避免反光和阴影；
- 一张拍不下就分几张，标上顺序。

## 老师：整理进网站

收到照片后：

1. 与同学核对原意，先确认知识点、例题与结论是否正确；
2. 按讲解顺序放进对应学科页面，融入已有的知识体系，而不是堆在页面末尾；
3. 公式与图表用现有 Markdown 能力重新表达，见[公式与图表](./math-and-charts.md)；
4. 按[贡献者与修改记录](./contributions.md)写清**实际内容贡献者**的协作昵称；只负责录入的人填在 `recordedBy`，不因代录而署名；
5. 暂时无法核实的结论写明待核对，确认后再定稿。

命名与放置规范见[一页笔记怎么写](./writing.md)；同伴与老师的审阅流程见[协作与审校](./collaboration.md)。

## 会改文件时：直接参与

这是可选方式，适合已经会用编辑器或 Git 的同学。

先读[一页笔记怎么写](./writing.md)，再把文件放进 `docs/notes/<学科>/junior/`、`senior/` 或跨学段的 `shared/`。在仓库根目录装好依赖后运行：

```sh
pnpm install --frozen-lockfile
pnpm docs:dev
```

改完后运行检查与构建，再按[协作与审校](./collaboration.md)送审：

```sh
pnpm docs:check
pnpm docs:build
```

提交、推送与发布由维护者按约定执行；提交次数不代表内容贡献。

## 常见问题

- **不知道自己写的是知识点还是考点**：不必纠结，按自己的理解写，整理时再归类。
- **只有一道题的解法可以吗**：可以。写清题目条件、思路和卡住的地方，比只给答案有用。
- **担心写得不对**：先写下来并标出疑问，老师会核对；不写下来反而没法用。
- **找不到 `pnpm` 或 Node 版本不符**：按仓库根目录 `README.md` 的说明准备 Node.js 24 LTS 与对应版本的 pnpm。
- **本地看不到贡献记录**：检查文章顶部是否填写 `noteContributors` 或 `noteChanges`，详见[填写教程](./contributions.md)。
