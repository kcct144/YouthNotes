# 一页笔记怎么写

## 先确定一页要解决的问题

围绕一个清晰的主题组织页面，注明学段、先修知识、学习目标。不要把不同学科、不同难度且没有联系的片段堆在一页。若某个结论只适用于特定教材、题型或条件，直接写清。

同一页可以有三类内容，也可以只有其中一类；还可以按子主题交替放置。使用二级、三级标题组织长内容，提示块用于突出关键内容，不必把整篇文章都装进提示块。

| 类型 | 应回答的问题 | 推荐内容 |
| --- | --- | --- |
| 知识点 | 是什么，为什么，何时成立？ | 概念、解释、条件、正例与反例、知识联系 |
| 考点 | 怎样识别问题，如何求解？ | 题型线索、适用方法、典型例题、完整解法与检验 |
| 坑点 | 容易怎么错，怎样发现？ | 错误做法、错因、反例或边界、自查动作 |

## 按类型给二级标题配色

需要强调分类时，在二级标题开头写 `【知识点】`、`【考点】` 或 `【坑点】`，整行标题会自动显示为蓝色、绿色或红色，浅色与深色模式均适配：

```md
## 【知识点】一次函数的概念

## 【考点】由两个点确定表达式

## 【坑点】不要漏掉非零条件
```

按需要使用，不强制每个二级标题都加标记。普通二级标题、其他级别的标题保持默认颜色；文字标记保留在正文和页内目录中，便于识别。“此页内容”的右侧目录与下拉菜单会沿用对应的蓝、绿、红配色，悬停或选中时保留分类颜色。完整效果见[一次函数示范](../notes/math/junior/linear-function.md)。

## 三类提示块

复制下面的语法即可。标题始终保留“知识点 / 考点 / 坑点”，让含义不只依赖颜色。

````md
::: tip 知识点 · 一次函数的条件
一次函数写作 $y=kx+b$，其中 $k\ne0$。
:::

::: note 考点 · 由两点求表达式
把两个点的坐标代入表达式，列方程求系数，再代回检验。
:::

::: warning 坑点 · 不要漏掉非零条件
$y=3$ 是常函数，不属于这里定义的一次函数。
:::
````

## 例题先给题干，解析可折叠

题干必须足够完整，让没有看解析的同学也能作答。标明原创或真实出处，不能把 AI 生成的题标为某年真题。

```md
### 例题（原创）

已知一次函数图像经过两个点……

<details>
<summary>展开思路与解析</summary>

这里写方法选择、推导、答案和检验。标签与 Markdown 内容之间留空行。

</details>
```

解析说明“为什么这样做”，坑点说明“怎样避免再错”。阅读时应能先尝试，再自行展开答案。公式和图表写法见[公式与图表](./math-and-charts.md)。

## 标题、链接和附件

每篇 Markdown 使用 `title` frontmatter：

```yaml
---
title: 你的主题
---
```

不需要手写 `permalink`；链接来自文件路径。贡献者名单与修改记录填写在文章顶部的 `noteContributors` 和 `noteChanges`，组件自动展示，写法见[填写教程](./contributions.md)。区分内容贡献者与代录人；没有确认的资料保持空列表，不根据 Git 提交者推断学生贡献。

移动旧文件时保留顶部共建记录，搜索并修复引用。正文链接优先使用相对 `.md` 路径，例如 `[相关主题](./other-topic.md)`。

图片与小附件可放在笔记旁的 `assets/`，使用 `![有意义的图片说明](./assets/diagram.svg)` 引用。图片内的文字不能替代正文；实验数据图还应附数据表或结论说明。

## 来源与不确定性

教材写名称、版本和章节；网上资料写真实链接及实际查阅日期；原创例题和自己生成的数据注明原创。只有确实核对过才写页码或真题年份。

发现争议时先记录适用条件和证据，交给老师或同伴核对。构建成功只代表网站能生成，不代表知识、题解与“常考”判断正确。
