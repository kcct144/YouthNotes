# 一页笔记怎么写

## 先确定一页要解决的问题

围绕一个清晰的主题组织页面，注明学段、先修知识、学习目标。不要把不同学科、不同难度且没有联系的片段堆在一页。若某个结论只适用于特定教材、题型或条件，直接写清。

同一页可以有知识点、考点、坑点、清单中的任意内容，不要求四类齐备，也不固定为四个大块。按主题的包含关系组织标题层级：知识点下可以有子知识点、考点、坑点和清单，考点下也可以补充所需知识点或子考点，各类可以自由交错。提示块只突出关键内容，不必把整篇文章都装进去。

| 类型 | 应回答的问题 | 推荐内容 |
| --- | --- | --- |
| 知识点 | 是什么，为什么，何时成立？ | 概念、解释、条件、正例与反例、知识联系 |
| 考点 | 怎样识别问题，如何求解？ | 题型线索、适用方法、典型例题、完整解法与检验 |
| 坑点 | 容易怎么错，怎样发现？ | 错误做法、错因、反例或边界、自查动作 |
| 清单 | 哪些条目要能查到、需要记到什么程度？ | 可枚举的事实与对照：焰色反应、离子颜色、常见沉淀、常数与单位，注明适用范围与出处 |

## 清单与知识点要分开

清单收的是**可以逐条核对的事实**，不承担原理。为什么会出现焰色、颜色为什么随浓度变化，写在知识点里；清单只给“元素—颜色”这类可查、可比对的结果，两者互补，不互相替代。

- 清单优先用表格，列数控制在能一屏读完；条目多时按类别拆成几个清单，不堆成一张超长表。
- 必须写明适用范围：温度、浓度、教材版本、实验条件中真正影响结论的部分。条件不明就先写清缺什么。
- 每条要有可追溯的来源；来源暂缺的条目标为待核对，不写“必背”“一定考”。
- 不把清单写成口诀堆。记不住的部分可以提示怎么记，但结论本身必须准确。

```md
#### 【清单】常见元素的焰色反应

| 元素 | 焰色 | 备注 |
| --- | --- | --- |
| 钠 | 黄色 | 酒精灯外焰观察，条件不同会影响判断 |

来源：教材名称、版本与章节；未经核对的条件写在“待核对”里。
```

## 标题分类与层级

二级至六级标题（h2–h6，即 `##` 至 `######`）统一支持开头的 `【知识点】`、`【考点】`、`【坑点】`、`【清单】` 标记。站点将分类文字排成小型标记，分别辅以蓝、紫、赭橙、青绿色；标题名称保持正文墨色。不需要手写 HTML 或 emoji，含义也不只依赖颜色。未加标记的普通标题保持原样。

标题级别表达内容的包含关系，不表达分类或重要程度。以下只是交错示例，可按内容删减，不必补齐任何类别：

```md
## 【知识点】一次函数

### 【知识点】系数与图像

#### 【考点】根据图像判断系数

##### 【知识点】判断所需的符号关系

###### 【坑点】不要忽略坐标轴方向

### 【考点】由两点确定表达式

#### 【考点】代入并检验

#### 【坑点】不要漏掉非零条件

#### 【清单】常见元素的焰色反应

## 小结
```

页内目录默认收录 h2–h3。确实需要显示下一层时，可在页面 frontmatter 中设置 `outline: [2, 4]`；不要为了展示分类把所有细节都塞进目录，也不要为了进入目录而扭曲标题层级。桌面与手机目录保持相同顺序、分类文字和具体标题，以细色线辅助辨认。原文与锚点不因标记样式改变。完整效果见[一次函数示范](../notes/math/junior/linear-function.md)。

## 三类提示块（清单不用提示块）

复制下面的语法即可。标题始终保留“知识点 / 考点 / 坑点”，让含义不只依赖颜色。清单的内容是成组的事实条目，用表格或正文即可，不要为它新造提示块，也不要把整张表塞进一个提示块里。

````md
::: tip 知识点 · 一次函数的条件
一次函数写作 $y=kx+b$，其中 $k\ne0$。
:::

::: note 考点 · 由两点求表达式
把两个点的坐标代入表达式，列方程求系数，再代回检验。
:::

::: warning 坑点 · 不要漏掉非零条件
$y=3$ 是常函数，不属于这里定义的一次函数。
:::
````

## 例题先给题干，解析可折叠

题干必须足够完整，让没有看解析的同学也能作答。标明原创或真实出处，不能把 AI 生成的题标为某年真题。

```md
### 例题（原创）

已知一次函数图像经过两个点……

<details>
<summary>展开思路与解析</summary>

这里写方法选择、推导、答案和检验。标签与 Markdown 内容之间留空行。

</details>
```

解析说明“为什么这样做”，坑点说明“怎样避免再错”。阅读时应能先尝试，再自行展开答案。公式和图表写法见[公式与图表](./math-and-charts.md)。

## 按需添加交互练习

练习不是每页必备内容。`NotePractice` 的写法以本节为唯一权威说明，其他模板和教程只链接到这里。练习应标注原创或真实出处，题干完整、条件明确，答案解析说明推导和检验。

### 单选：选择、提交与反馈

```md
<NotePractice mode="single" answer="B" choices="A,B,C,D" title="专项练习（原创）">

下列哪个数满足 $x>0$？

<template #option-a>

$-2$

</template>

<template #option-b>

$3$

</template>

<template #option-c>

$0$

</template>

<template #option-d>

$-1$

</template>

<template #hint>

正数在数轴上位于原点右侧。

</template>

<template #answer>

答案为 B。$3>0$，其余选项均不大于 $0$，因此只有 B 满足条件。

</template>

</NotePractice>
```

单选使用原生 radio，选择后点击“提交答案”才显示判断；可以用方向键改选，再提交继续尝试，并可按需展开提示、答案或重做。改选会清除上次判断，重做会清空选择并收起提示与解析。这只是当前题目选项的正误反馈，不是考试成绩、能力评估或完整学习记录。

### 自查：草稿与答案对照

```md
<NotePractice mode="self" title="对照自查（原创）">

解方程 $x+2=5$，写出过程并检验。

<template #hint>

等式两边同时减去 $2$。

</template>

<template #answer>

两边同时减去 $2$，得 $x=3$。代回原方程，$3+2=5$，因此解为 $x=3$。

</template>

</NotePractice>
```

自查模式提供草稿 textarea，读者自行展开答案对照；不自动评分，不自动判定计算题、证明题或文字解答是否正确。可重做以清空本次练习。

### 属性与插槽约定

| 接口 | 写法与用途 |
| --- | --- |
| `mode` | 显式选择 `single`（单选）或 `self`（自查）。 |
| `title` | 练习标题，例如 `专项练习（原创）`；按实际来源填写。 |
| `choices` | 仅单选设置，用逗号分隔 2–6 个不重复的大写字母，如 `A,B,C,D`（默认值）；与选项插槽逐一对应。自查不设置。 |
| `answer` 属性 | 仅单选设置正确选项标识，如 `B`，必须在 `choices` 中；自查不设置。它不能代替答案解析插槽。 |
| 默认插槽 | 只写题干及必要条件；不要在选项或答案插槽再维护一份题干。 |
| `#option-a` / `#option-b` / `#option-c` / `#option-d` | 各自写对应选项的 Markdown 内容，支持公式；仅单选使用。 |
| `#hint` | 可选提示，不直接替代完整解析。 |
| `#answer` | 两种模式都必须提供完整答案解析，说明思路、过程、结论及必要检验。 |

Vue 标签、插槽标签与 Markdown 内容之间留空行。公式放在题干、选项、提示或解析的 Markdown 中，经现有 KaTeX 渲染，不把复杂公式塞进字符串属性。

题干、选项和答案解析不能留空；缺失或为空时显示配置错误，不提供可作答的判断控件。提示可以省略。

答案随页面公开发送到客户端，折叠只是阅读辅助，不是保密措施，不能用于保密考试。练习无需账号，没有后端作答记录；选择与草稿仅在当前页面临时使用，刷新或离开页面即清空，不保存到服务器。两种模式都提供重做，不应宣传为自动评分系统或持久学习档案。

## 标题、链接和附件

每篇 Markdown 使用 `title` frontmatter：

```yaml
---
title: 你的主题
---
```

不需要手写 `permalink`；链接来自文件路径。贡献者名单与修改记录填写在文章顶部的 `noteContributors` 和 `noteChanges`，组件自动展示，写法见[填写教程](./contributions.md)。区分内容贡献者与代录人；没有确认的资料保持空列表，不根据 Git 提交者推断学生贡献。

移动旧文件时保留顶部共建记录，搜索并修复引用。正文链接优先使用相对 `.md` 路径，例如 `[相关主题](./other-topic.md)`。

图片与小附件可放在笔记旁的 `assets/`，使用 `![有意义的图片说明](./assets/diagram.svg)` 引用。图片内的文字不能替代正文；实验数据图还应附数据表或结论说明。

## 来源与不确定性

教材写名称、版本和章节；网上资料写真实链接及实际查阅日期；原创例题和自己生成的数据注明原创。只有确实核对过才写页码或真题年份。

发现争议时先记录适用条件和证据，交给老师或同伴核对。构建成功只代表网站能生成，不代表知识、题解与“常考”判断正确。
