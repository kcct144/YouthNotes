# 协作与审校

## 学生先贡献内容

学生可以在课堂讲解、提出问题、提供原创例题或反例，也可以交纸质笔记、批注和图示。通过老师约定的方式说明准备补哪个主题，保留原意与疑问，不要求先注册 GitHub 或操作电脑。

## 维护者整理与代录

老师或其他维护者把材料整理进对应页面。先确认知识与题解，再与学生核对表达；不能因为由老师操作电脑，就把所有内容署名为老师。

在文章的 `noteContributors` 写协作昵称和实际贡献，在 `noteChanges` 写本次变更、实际内容贡献者及可选的代录人。具体写法与演示见[贡献者与修改记录](./contributions.md)。只负责录入的人填写在 `recordedBy`，如有实质讲解或审校贡献，再如实列入名单。

## 同伴与老师审阅

同伴检查能否看懂、题目能否独立完成、解析是否跳步、链接和图表是否可用；老师核对知识与教学范围、题型归纳和答案。反馈指出具体段落、理由与建议。

共同核对昵称、贡献说明与修改记录，确认没有遗漏或误记。暂时无法解决的学科分歧，写清条件和来源，请老师确认。

## 维护者检查并保存

在本地预览公式、图表和共建记录，运行：

```sh
pnpm docs:check
pnpm docs:build
```

CI 也会运行检查与构建；知识和署名的真实性仍需人审。Git 用于保存文件版本和回退操作，页面上的贡献者名单与修改记录以文章中填写的内容为准。

## 会使用 Git 的同学可以直接协作

这是可选方式。先与老师确认仓库地址与权限；没有写权限时可以 Fork，再通过 PR 送审。下面以 `master` 为例，实际主分支为 `main` 时请替换。

```sh
git switch master
git pull --ff-only
git switch -c notes/math-linear-function
```

本地配置自己的提交昵称和隐私邮箱，按实际修改文件暂存，不提交缓存、构建目录或个人资料。检查通过后可以使用编辑器的 Git 界面提交、推送并发起 PR。

提交信息与 PR 说明写清修改目的、来源和待核对项；按照实际贡献维护文章中的名单与记录，不把 Git 操作次数当作内容贡献。提交、推送、合并与部署由维护者决定，AI 按用户当次明确要求执行。

发生冲突时逐段比较两个版本，保留有效解释及双方的真实贡献记录，合并后重新检查，不通过强制推送覆盖对方工作。
