# 贡献者与修改记录

贡献来自讲解、提问、纠错、提供例题、绘图或审校。学生可以通过课堂发言、纸笔材料或老师约定的方式参与，由维护者整理进网站，不需要电脑或 GitHub 账号。

::: warning 本页为填写演示
本页的昵称、日期和事件都是演示数据，不代表真实师生的署名或工作记录。正式笔记只填写已确认的真实贡献；没有资料时保持空列表。
:::

[直接查看本页底部的组件演示](#note-records)。

## 谁贡献内容，谁代为录入

| 信息 | 填写什么 |
| --- | --- |
| 贡献者名单 | 参与这篇笔记的协作昵称，以及每个人具体贡献了什么 |
| 修改记录中的内容贡献者 | 对这次内容变更有实际贡献的人，可填多人 |
| 代录人 | 帮忙把材料输入、整理进文件的人；仅代为操作不会自动变成内容贡献者 |

例如，同学提出一个有效反例，老师代为录入：内容贡献者填写同学，代录人填写老师。如果老师同时进行了实质讲解或审校，也可以在对应记录中列为贡献者。

## 在文章顶部填写

组件会读取文章顶部的两项数据，自动显示在正文下方，不需要手写 HTML，也不需要维护另一份名单。

```yaml
---
title: 一次函数
noteContributors:
  - name: 同学甲（示例）
    contribution: 提供截距为正但函数递减的反例。
noteChanges:
  - date: '2026-10-31'
    summary: 补充 y=-x+2 的反例，说明增减应看斜率。
    contributors: [同学甲（示例）]
    recordedBy: 老师（示例）
---
```

复制后替换为真实材料。`noteContributors` 中同一个昵称只写一项，可在贡献说明中合并多个方面；`noteChanges` 每次新增一条。`recordedBy` 可以省略，适合贡献者自行录入或不需要单独记录代录人的情况。

日期使用带引号的 `YYYY-MM-DD`，填写实际内容变更日期。提交或上传时间与课堂贡献时间不同，可以在修改说明中解释，不猜测未确认的日期。历史按日期从新到旧显示，同一天保留文件中的顺序；默认展示最近五条，其余可展开。

## 暂无资料时

```yaml
noteContributors: []
noteChanges: []
```

这会显示待填写状态。两个字段都省略时，整块共建记录不显示，适合学科目录等入口页。一次函数示范与笔记模板使用空列表，避免把演示人物当作真实贡献者。

## 变更怎么记

记录概念修正、补充例题、增加反例、审校结论或结构调整等有意义的变更，写清改了什么和谁参与。小的排版修改不必逐条记录；真实协作贡献不因修改很小而被忽略。

每条修改记录里的贡献者都应出现在本页名单中，代录人不必列入名单。使用固定协作昵称；同名者约定可区分的昵称，不公开学号、班级名单、联系方式或账号信息。

## 移动、拆分与合并文章

移动或改名时连同顶部记录一起保留，署名不依赖 Git 对文件移动的识别。网址仍来自文件路径，因此要同步修复链接。

拆分或合并时，根据保留的实际内容整理贡献者和相关历史，补一条真实的整理记录；不要把与新文章无关的整份名单照搬过去，也不要因为换了录入人而覆盖原贡献者。

## 检查记录

运行 `pnpm docs:check`，会检查名单、贡献说明、日期、重复昵称和修改记录中的署名引用；开发与生产构建也会拦截格式错误。它只能验证数据格式，真实贡献仍需由师生核对。
